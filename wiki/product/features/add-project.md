# Add a project

A project is a record in `projects.toml` (in Foreman's HQ; this machine's part, its profile and where each repo is, in its database) plus [its folder](../models/project-config.md#the-projects-folder) in Foreman's folder (`projects/<id>/`), holding its [HQ](../models/project-config.md#the-projects-hq) (`projects/<id>/hq/`) and its files; its agents' worktrees are in `worktrees/<id>/`, and its code repos live anywhere in the CEO's home folder ([Project config → The project record](../models/project-config.md#the-project-record)). Foreman derives every path from its folder and the project's id: the CEO picks none. A code repo is one the CEO already has, a new empty one Foreman creates at a path the CEO picks, or one **cloned** from its URL into Foreman's `repos/` ([Cloning a repo](#cloning-a-repo)), always with the CEO's own git.

## The dialog

A modal ([App shell](./app-shell.md#overlays)) opened from **`+ New project`** in the sidebar and from the checklist's **A project** row ([First run](./first-run.md#the-checklist)), fresh at each opening. One step, then the project's Repos page:

1. **New project**: the **Project name** (any words, made a slug: [Names](#names)), then the **HQ**, a segmented New | Clone:
   - **New**: "The project's wiki and project.toml, in a new git repo: its hq/ folder. One left there by a removed project is taken over as it is."
   - **Clone**: a field for a git URL or a local path ("Cloned with your own git: your SSH keys and credential helper. Foreman stores nothing."). The button reads `Cloning…` while it runs.

   **Create project** (Enter too) calls `POST /api/projects`; a refusal shows under the fields, git's own message for a failed clone. On success the dialog closes and the project's [Repos](./repos.md) page opens, to add its code repos there (the CEO, 2026-11-04), with the toast `<name> created` ("Made its HQ at <path>, with project.toml and a starter wiki.", "Cloned its HQ into <path>.", or, for a [takeover](#effect), "Took over the HQ left at <path>, as it was.").

## Picking repos

In [Repos](./repos.md#the-list), **Add a repo** opens on **Clone from a URL**. Enter a Git URL, review the prefilled name, and select **Clone repo**. To use a local folder, choose **A folder** and browse to it.

Both kinds take one **Name**, any words (one line, at most 80 characters): the server makes the repo's id from it ([Names](#names)). There is no id field: the hint under Name shows it live, "Its id: ledger-api. It shows as “Ledger API”.", or "Any words: they become its id, in lowercase with hyphens." while the words make no id (**Add repo** / **Create repo** greyed then). The clashes the server would refuse (the id `hq`, another repo's id, another repo's shown name, case aside) show under the hint as the words are typed, in the server's own words ([Refusals](#refusals)), and grey the button.

- **A git repo's top folder**: it is added as it is. One already in the project (by real path, so through a symlink too: the browser asks with `?project=`) has **Add repo** greyed and says "Already in this project, as <shown name>.". **Name** is prefilled from the folder's name as the words its id is made of (`readable(slug(folder))`: `foreman_ui` → "Foreman ui") and follows the folder until the CEO edits it. The hint goes on: "The folder keeps its name; agents see the repo as <id>." A repo without a `main` branch also shows **Default branch**, a select of its branches (the checkout's preselected): "This repo has no branch named main. Pick its default: agents start their branches from it, and merges go to it unless the lead names another branch. You can change it later in Repos." ([Project config → The project record](../models/project-config.md#the-project-record)). **Add repo**.
- **Any other folder**: a new empty repo goes in it. **Name** starts empty (placeholder "My repo"), and the new folder is named by the id: "Its id: ledger-api. It shows as “Ledger API”. Not a git repo: creates <folder>/ledger-api, a new repo with a README in a first commit, on main. Open a repo's folder above to add it instead." **Create repo**.

A name typed is kept while the CEO browses among folders of the same kind; opening a repo after a plain folder (or the other way) drops it, so a new repo's name never lands on a repo to add, nor a repo's on a new one. The form uses the UI's normal font, not Mono.

**The folder browser** (`FolderBrowser`, from `GET /api/folders?path=&project=` (`{path, home, repo, added?, foreman?, entries}`), behind the [access token](../architecture/security.md#access-token) like every request) shows one folder at a time: its path on top as **breadcrumbs** from the home folder (each folder above the one shown opens it; nothing above `$HOME` shows), then its subfolders by name (case-insensitive), hidden ones (dot folders) left out, on `--term` (darker than the dialog in the dark theme), each a row that opens it with a 16px icon: a folder, or a branch in `--ok` for a git repo's top folder (its own `.git` folder). **Foreman's own folders** (in Foreman's folder, by real path: `hq/`, `projects/` and `worktrees/`) show with their own icon (a folder with a mark, `--accTx`) and what they are (`Foreman's HQ`, `Foreman's projects`, `the agents' worktrees`), and don't open (the CEO, 2026-11-04): nothing in them is a code repo (the HQs are git repos, but not code). Foreman's folder itself opens, and so does its `repos/`, where a code repo is fine. Shown, should the browser start in one, **Add repo** and **Create repo** are off. A folder that can't be opened (gone since it was listed) says why. No pasted path (the CEO, 2026-11-04: out). It opens at the folder `foreman` was started in (its real path, or `$HOME` when that is outside `$HOME`), a convenience, and goes up to `$HOME`, never above. A folder outside `$HOME`, given by path, is refused (`400 INVALID`); a subfolder whose real path leaves `$HOME` (a symlink out) or is inside Foreman's home isn't listed. A browser can't tell where a dropped folder is on disk, by design: hence Foreman's browser.

**Never in Foreman's own folders** (the CEO, 2026-11-04): a code repo added, created or located inside Foreman's HQ, `projects/` or `worktrees/` (real paths, so through a symlink too) is refused (`400 INVALID`, "… is in <what>, Foreman's own: no code repo goes there"), whichever way the path comes; the browser never opens those folders.

**`$HOME` bounds every path, never inside Foreman's home** (the CEO, 2026-10-28, replacing the start-folder bound of 2026-10-20): a code repo, whichever way it comes (the browser, a pasted path, **Locate**, a new empty repo's folder), by its real path. A path outside is refused with the reason ("… is outside your home folder (…)", "… is inside Foreman's home (…)").


### Cloning a repo

The CEO, 2026-11-15 ([Portable projects](../../backlog/portable-projects.md)). The **Clone from a URL** tab shows a URL and the **Name** (prefilled from the URL's last part without `.git`, as the words its id is made of: `git@github.com:me/ledger-api.git` → "Ledger api", until the CEO edits it; the same hint and live refusals as a folder's: "Its id: ledger-api. It shows as “Ledger api”."), then **Clone repo** ("Cloning…" while git works). It goes to `repos/<the URL's path, without .git>` in Foreman's folder (`me/ledger-api`; a GitLab subgroup keeps its groups: `acme/platform/deploy`), Foreman's only place for clones, with the CEO's git (their SSH keys, agent, credential helper; never a prompt). Its default branch is `main` when it has one, else the branch the remote's checkout is on (Repos changes it). `POST /api/projects/{id}/repos {name, clone, defaultBranch?}`, its id made from the name ([Names](#names)):

- Only a URL with a host: `ssh://`, `git@host:path`, `https://`, `http://`, `git://`. A local path (or `file://`) is refused: pick its folder. So is a URL whose path isn't folders Foreman can make (each part a [repo name](#names): no `..`, nothing hidden, nothing empty).
- **A clone already there** can be shared by several projects. Its saved origin must have one fetch URL and be free of embedded credentials. Move any credentials to your host's Git credential helper before sharing the checkout.
- Foreman compares the configured URLs and asks Git where each would fetch after applying `insteadOf` rules. Both comparisons must match. Standard GitHub spellings such as `git@github.com:agentic-wiki/something`, `ssh://git@github.com/agentic-wiki/something.git` and `https://github.com/agentic-wiki/something.git` match when the literal owner and repo path agree. The `.git` suffix and explicit default ports are optional. Other spellings require the same configured URL after credential removal. Rewrites to other servers must produce identical destination URLs.
- If another remote maps to the same folder, Foreman leaves the checkout intact and returns `409 EXISTS`. Clone the desired repo into a separate folder and select **A folder** to add it.
- A clone that fails (`400 INVALID`, git's message), or a step after it, leaves nothing: the clone and the folders it made go. A clone once added is the CEO's, like any repo: never moved or deleted by Foreman, a removal included.
- The URL's https user and password, if any, stay in the clone's own `.git/config` (the CEO's machine); `projects.toml` keeps it without them.

## Names

A **project's name** is a slug (the CEO, 2026-11-02): lowercase letters and digits in words joined by single hyphens (`my-portfolio`), at most 63 characters; it is the project's id and names its folders (`projects/<id>/`, `worktrees/<id>/`), and the UI shows it readable ("My portfolio", [Project config → The project record](../models/project-config.md#the-project-record)). The dialog takes any words and makes the slug as the CEO types (accents dropped, anything else between words a hyphen: `My Portfolio!` → `my-portfolio`), its hint saying `Its id: <slug>, in projects/<slug>/ of Foreman's folder. It shows as “<the words typed, trimmed>”.`. Projects made before keep their names (`Ledger.v2` still works, shown as it is). Its refusals read as in [Refusals](#refusals). The words typed are kept too, as its [display name](../models/project-config.md#the-project-record) (`My Café!` shows as `My Café!`, not `My cafe`), unless they read as the id made readable, then stored as `""`; the CEO changes it later in Project settings. The id never changes.

A **repo's name** is any words, one line, at most 80 characters, the same rule as a project's display name (the CEO, 2026-11-19). Its **id** is always made from it, on the server, when it is added and on every rename, by `slug`: NFD, every nonspacing mark removed, lowercase, each run of anything but `a-z` and `0-9` one hyphen, hyphens trimmed at both ends, cut to 63 characters and trimmed again (`Ledger API` → `ledger-api`, `  My  Café! ` → `my-cafe`; letters that don't decompose, such as æ, ø and ß, are dropped, not transliterated: the hint shows the id as the CEO types). One rule for Foreman: the UI's `slug` is its twin, and both are tested against `internal/home/testdata/slugs.json`. Agents only ever see the id; people see the name, or the id made readable when it has none (a name that reads as the id made readable is kept as `""`). A name that makes no id ("!!!", "日本") or makes `hq` (the HQ's id, in the `commit` tool and the repos list) is refused, and so is one whose id another repo of the project has, or that another repo already shows, in any case: a Mac's filesystem takes `Ledger` and `ledger` for one, and elsewhere they would be two names hard to tell apart. **Repos added before** keep their ids (`Ledger_API`, shown as "Ledger API") until renamed; no new repo may show as one of them. The refusals, word for word, are [below](#refusals).

### Refusals

Every refusal of a name, for repos and projects, as the server sends it (`error`) and the UI shows it live: one full sentence, saying what to do when there is something to do.

| Code | When | Message |
|---|---|---|
| 400 INVALID | a name over 80 characters (repos, projects) | A name has at most 80 characters. |
| 400 INVALID | a name of several lines (repos, projects) | A name is one line. |
| 400 INVALID | a repo name that makes no id (empty, "!!!", "日本") | A repo's name needs a letter or digit (a–z, 0–9): its id is made from them. |
| 400 INVALID | a repo name whose id would be `hq` | “HQ” is the project’s HQ: pick another name. |
| 409 EXISTS | a repo name whose id another repo has, in any case | Another repo has the id <id> already: pick another name. |
| 409 EXISTS | a repo name another repo already shows, in any case | Another repo shows as “<shown>” already: pick another name. |
| 409 EXISTS | a rename whose worktree target exists | <path> is in the way: move it, then rename again. |
| 409 DEPLOYED | any repo rename while a team is deployed on the project | Stop the team on this project first to rename a repo. |
| 409 DEPLOYED | removing a repo while a team is deployed on the project | Stop the team on this project first to remove a repo. |
| 400 INVALID | renaming a repo whose id changes while it has a problem (missing, moved) | <id> has a problem (<problem>): locate it first, then rename it. |
| 409 DEPLOYED | locating a repo while its rename made on another machine waits for the team here to stop | Renamed from <old-id> on another machine: stop the team here, and Foreman follows. |
| 400 INVALID | a project id off the rule | A project id is lowercase letters, digits and single hyphens, at most 63 characters (my-portfolio). |
| 409 EXISTS | a project id another project has, in any case | Another project has the id <id> already: pick another name. |
| 409 EXISTS | a project name another project already shows, in any case | Another project shows as “<shown>” already: pick another name. |

The repo's problems while a rename made on another machine waits to be followed: "Renamed from <old-id> on another machine: stop the team here, and Foreman follows." (also the refusal to locate it meanwhile, above) and "<path> is in the way: move it, and Foreman follows." ([Project config → A rename made on another machine](../models/project-config.md#a-rename-made-on-another-machine)). The UI shows the server's `problem` as it is.

## Effect

`POST /api/projects {id, name?, clone?}` ([API](../architecture/api.md)): `id` the slug, `name` the words typed. Without `clone`, **New**:

1. Refuses an id that breaks the rules, or a name that breaks a display name's (at most 80 characters, one line) (`400 INVALID`); `409 EXISTS` for an id another project has, or for a name another project already shows (in any case); without a name, the id made readable counts as the name.
   **An HQ already there** (`projects/<id>/hq/`, left by a project removed with its HQ kept) is **taken over** as it is, its history and edits included, with no new commit: steps 2 to 4 are skipped and the record is made (the CEO, 2026-10-20; the place redefined 2026-10-28). Only a git repo's own top folder is taken over; otherwise `409 EXISTS` with what to do: Clone asked for ("create the project without Clone to take it over, or move it away"), or not a git repo, a symlink included ("move it away"). A failed takeover never deletes that folder. The answer is `201` for an HQ made or cloned, `200` for one taken over, so the dialog can say which.
2. Creates `projects/<id>/hq/` and its missing parents.
3. Writes `project.toml`, the scaffold's first file (`internal/home/starter/project.toml`), with the defaults ([Project config](../models/project-config.md)): an empty `checks`, the gates as a commented-out starter list (`# always_ask_ceo = ["new dependency", "touches shared staging"]`) so the CEO sees the option.
4. Creates the **scaffold**: the HQ's files besides `project.toml`, from Foreman's starter, a folder laid out as in the repo and built into the binary (`internal/home/starter/`, `{project}` standing for the project's name). One definition, also used to [fill an HQ that lacks them](./wiki-reader.md#no-wiki-yet). The default is modelled on Foreman's own wiki and workflow (the CEO, 2026-10-17):
   - **`AGENTS.md`**, at the HQ's root, ignored by the wiki: the project's conventions for its agents, in one file. How to operate the wiki with the `wiki` command (`wiki --root "$PROJECT_HQ"`); the structure below (technical debt kept as one page; decisions written into the spec they change, no folder of their own); specs (`status: planned | partial | built`, open questions in the spec); one task entry per task in `backlog/` (`type: task`, `title`, `status` among `backlog` (unscheduled), `todo` (scheduled), `blocked` (with a `Blocked by` line in the body saying on what), `in-progress` (also while reviewed), `done`, and no other (the CEO, 2026-10-17: five statuses, since a board shows any other as a column of its own), `priority` among `quick`, `high`, `medium`, `low`, `assignee` as an agent id, `epic`, a work-kind tag); epics in `backlog/epics/`; the lifecycle (capture, work, finish, retire); technical debt; the queries. The lead alone writes the wiki and keeps the board true, committing with `commit()`; everyone else uses `contribute()`. Every session prompt points agents at it ([Session prompt](../architecture/session-prompt.md)).
   - **`wiki.toml`**, the wiki at the HQ's root (the CEO, 2026-11-04: `backlog/` reads better than `wiki/backlog/`): `types = ["spec", "task", "epic", "note"]`; `backlog/**` kept out of `wiki orphans` (`inbox/**` too until the CEO, 2026-11-18, when contributions left the HQ); `AGENTS.md` ignored (the HQ's operating doc, not an entry; an HQ made before 2026-11-20 also ignores a `README.md` the starter never wrote, which `wiki` v0.19.0 and later warns about: delete `"README.md"` from its `ignore` by hand); three boards, the two over tasks laned by priority (`lanes = ["quick", "high", "medium", "low"]`; `quick` is work with no uncertainty, doable right now): **Board**, the scheduled tasks (`status!=backlog`) in the columns `todo`, `blocked`, `in-progress`, `done` (the CEO, 2026-10-17: about four columns as a start; `review` went, since reviewed work is still in progress); **Backlog**, the unscheduled tasks and the scheduled ones not started yet in `backlog` and `todo`: its `where` leaves out every status of work started or ended, ours (`blocked`, `in-progress`, `done`) and the usual others an agent might use instead (`doing`, `wip`, `review`, `in-review`, `testing`, `closed`, `cancelled`, `canceled`, `wontfix`, `archived`), so a stray status never lands on it: a card moved to `todo` stays there and shows on Board too (the CEO, 2026-10-17); and **Epics**, the epics by status (the CEO, 2026-10-17: two task boards rather than six columns).
   - **`.gitignore`**, at the repo's root, with defaults that fit any HQ (the CEO, 2026-10-17): the `wiki` command's index (`.wiki/`), secrets (`.env`, `.env.local`), and operating-system and editor clutter (`.DS_Store`, `Thumbs.db`, `desktop.ini`, `*.swp`, `*~`, `.idea/`, `.vscode/`, `.obsidian/`). A project made before it gets the usual notice and `Create it`.
   - **`index.md`**, titled with the project name, linking product, backlog and technical debt, and saying "Deploy a team from this project's Team section."
   - **`spec/index.md`** (the spec map; `product/` until 2026-11-16, the CEO), **`backlog/index.md`** (the current goal and the queries), **`technical-debt.md`**.
   - Nothing optional: `research/`, `spec/glossary.md` or another folder (`discovery/`, `issues/`…) is described in AGENTS.md and created by the lead when there is something to put in it, never as an empty placeholder that invites agents to fill it (the CEO, 2026-10-17).

   The new wiki passes `wiki check`. The wiki can't be read without `wiki.toml` and `index.md`; the rest it reads fine without. The lead creates everything else. Then runs `git init` (on `main`) and commits `project.toml` and the scaffold as the repo's first commit, "Project HQ".
5. Creates the project's record: its entry in `projects.toml` (no repos; its display name; its HQ's origin for a clone), one commit to Foreman's HQ, and its row in this machine's database (the default profile). A row left there with no entry (one the CEO took out of `projects.toml` by hand) goes first, its history with it: the new project starts clean. Refused (`400`) while `projects.toml` has problems, leaving nothing behind. Its `files/inbox/` and `files/shared/` are made beside the HQ (every project has them, made again if gone).

With `clone` (a git URL or a local path), **Clone**: the same refusals, then `git clone` into `projects/<id>/hq/` with the CEO's own git on the host (their SSH keys, agent and credential helper; Foreman stores nothing), then the record. A local folder is copied, never moved in. Hardened, since the source is typed in: only the `https`, `http`, `ssh`, `git` and `file` transports (`protocol.allow`), a source starting with `-` refused, `--` before the arguments, and no terminal to prompt on (a session of its own, `GIT_TERMINAL_PROMPT=0`), so a source that wants a password fails with git's message instead of hanging. A failure is `400 INVALID` with git's message. The clone is taken as it is: one without `project.toml` or a wiki shows the usual notices and their `Create it` ([Wiki reader → No wiki yet](./wiki-reader.md#no-wiki-yet)).

Nothing is left behind if a step fails: the folders the call made are removed whole (a taken-over HQ stays). Marking every existing wiki entry as seen is not built yet: it needs the [UI state](../models/ui-state.md) API.

## Code repos

A project starts with none, and deploying refuses until it has one. Each route that takes a `name` makes the repo's id from it ([Names](#names)). Each answers with the project, or a refusal that says why (`400 INVALID`, `409 EXISTS`, `409 DEPLOYED`):

- **Add** an existing repo, `POST /api/projects/{id}/repos {name, path, defaultBranch?}`: an absolute path to a git repo's top folder (its `.git` a folder), with at least one commit, inside `$HOME` and outside Foreman's home ([Picking repos](#picking-repos)), and not already in the project. Its default branch is its `main` branch when it has one; otherwise the request's `defaultBranch` names one of its branches, and a missing or unknown one is refused (`400 INVALID`). `GET /api/folders/branches?path=` lists a folder's branches and its checkout's, for that pick. A repo may be in several projects.
- **New** empty repo, `POST /api/projects/{id}/repos {name, path, new: true}`: a `path` that doesn't exist yet, in a folder that does, inside `$HOME` and outside Foreman's home. Foreman creates it on `main`, its default branch, with a `README.md` in its first commit (so agents' branches have a `main` to start from), and removes it if a later step fails.
- **Default branch** of a repo, `PUT /api/projects/{id}/repos/{repo}/default {branch}`: one of its branches but an agent's (`wt/*`, `lead/*`), else `400 INVALID`. It just sets it, allowed while a team is deployed: worktrees made before stay on their branches; new branches and merges use the new one, and open merge requests keep the branch they go into.
- **Locate** a moved repo, `PUT /api/projects/{id}/repos/{repo} {path}`: inside `$HOME`, and the folder must hold the repo's root commit. Existing worktrees follow it (`git worktree repair`) on the next start. Or `{clone: true}`: cloned from the remote its record keeps, as [Cloning a repo](#cloning-a-repo) says (a clone already there must hold the root commit), refused when none is kept or the clone isn't the same repo (it goes again).
- **Rename** a repo, `PUT /api/projects/{id}/repos/{repo}/name {name}`: refused while a team is deployed on the project ("Stop the team on this project first to rename a repo.", `409 DEPLOYED`). The new name follows the [rules](#names), the repo itself left out of the clashes, and its id is made from it again. When the id stays, only its display name changes (one commit to `projects.toml`). When it changes (an older `Ledger_API` renamed "Ledger API" becomes `ledger-api`), the repo can't have a problem (locate it first); each agent's existing worktree moves to the new id (`git worktree move`; a change of case only in two moves, as a Mac's filesystem sees one folder), so stopped deployments keep their work, and a worktree already at the new id refuses it ("<path> is in the way: move it, then rename again."); if one fails, those moved go back. The project's **open** merge requests on the repo follow the new id, in the same transaction as this machine's record, then `projects.toml` is written (one commit); closed ones keep the old id, their history (the CEO, 2026-10-20). Another machine follows the rename when it loads `projects.toml` ([Project config → A rename made on another machine](../models/project-config.md#a-rename-made-on-another-machine)).
- **Remove** a repo, `DELETE /api/projects/{id}/repos/{repo}`: refused while a team is deployed on the project ("Stop the team on this project first to remove a repo.", `409 DEPLOYED`). Its folder and branches stay.

## Removing a project

`DELETE /api/projects/{id}` (`?deleteHQ=true`, `?deleteWorktrees=true` for the options), `204` on success, from **Remove this project** in [Project settings](./project-settings.md). Any project can be removed, [hidden](../models/project-config.md#the-project-record) or not (the CEO, 2026-11-13: archiving first, required until then, only repeated the confirmation), but never while a team is deployed on it (`409 DEPLOYED`). In order:

1. Its entry in `projects.toml` goes, one commit to Foreman's HQ (so it is removed from every machine the HQ reaches), then its record and its **history** in this machine's database, in one transaction: deployments, instances, team messages, actions, work items, merge requests, requests (the CEO, 2026-10-20). Ids are built from the name (`atlas@ledger`), so a redeploy after re-adding the name would otherwise revive the old rows: re-adding it starts clean. Refused, with nothing removed, while `projects.toml` has problems.
2. With the worktrees option (off by default), its agents' sandboxes (`worktrees/<id>/`) go, uncommitted work included, and each code repo prunes its worktrees' records (`git worktree prune`). The repos and their branches stay. Without it, they stay (the CEO, 2026-10-28); their branches can't be deleted while checked out there. On a project kept, Deployment's [Clean up](./project-team.md#earlier-teams) removes earlier teams' worktrees, those holding uncommitted work only when asked.
3. Its session logs (`~/.foreman/logs/*@<id>/`) and its agents' harness folders (`~/.foreman/harness/<id>/`: their conversations) go.
4. With the HQ option (off by default), its HQ goes too ("Also delete its HQ, <path>: its wiki and project.toml. Unless you pushed it, it has no other copy. Kept, a new project of the same name takes it over."). Without it, it stays, and a new project of the same name takes it over ([Effect](#effect)).
5. Its `files/` stay, the CEO's. `files/inbox/`, `files/shared/`, `files/`, `worktrees/<id>/` and `projects/<id>/` go only when left empty.

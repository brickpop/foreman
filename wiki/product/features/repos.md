# Repos

A project's **Repos** section ([Project page](./project-page.md); Repositories until 2026-10-31): the project's repos, listed and managed, each opening its own page with its files and history by branch, read-only and as committed. Decided by the CEO on 2026-10-17 ([Repositories card](../../backlog/archive/project-code-tab.md)); only the repos since 2026-10-21, when the work in flight and what merged moved to [Deployment](./project-team.md) (the CEO). Body padding `24px 24px 48px`.

## The list

`/projects/<project>/repos`, at most 920px wide. Under the [project's bar](./project-page.md#the-projects-bar) (`<project> · Repos`), its actions on the right (the CEO, 2026-11-16): **Clean up branches** (while the project has a code repo), then **Add a repo**, rightmost. Under it, a grid of **cards** (at least 260px wide, 12px apart; the CEO, 2026-11-02, replacing a panel of rows), one per code repo of the [record](../models/project-config.md#the-project-record), then the project's **HQ**'s. The CEO moved them here from Settings on 2026-11-01: the repos are managed where they are read.

- **A card** (a [card](../design/design-system.md#surfaces), as the Dashboard's: the name and the `⋯` menu in its header band, the rest in its body, 6px apart) opens the repo's page wherever it is clicked (hover border `--line3`), except a repo with a problem, which can't be read. On it:
  - its **name** (600 15px; the CEO, 2026-11-02: not a path): its display name, else its id as words (`repoName`; the CEO, 2026-11-19: [Add a project → Names](./add-project.md#names)): hyphens and underscores read as spaces, the first letter capital, so `foreman-ui` is "Foreman ui". Only how it shows: the repo's id, its folder name, the URL and every other place a repo is named (branch lines, reviews) keep `foreman-ui`. Its id is the name's tooltip;
  - its path (Mono 12px `--tx4`);
  - its default branch (Mono) followed by `(default)`, and `· N branches` (12.5px `--tx3`); or, for a repo with a problem, the problem in `--err` (a missing folder, or one that is another repo: `Locate it where it went, or remove it from the project`);
  - when the repo no longer has its default branch, in `--err`: "No branch <default>: pick its default branch, or agents can't start." (the CEO, 2026-10-21);
  - a **`⋯` menu** (above the card's link): **`Default branch…`** (**`Locate…`** instead for a repo with a problem), **`Rename…`** and **`Remove…`**.
- **The HQ's card**: "HQ", "project.toml and the wiki", its branch count; no menu. Until the repos are read, a card-sized [loading placeholder](../design/design-system.md#surfaces) holds its place in the grid (never a full-width row under it).
- With no code repo, above the cards in `--tx3`: `No code repo: agents work in the project's wiki only. Add one for them to write code.` (a research team needs none: [Team tools → No code repo](../architecture/team-tools.md#no-code-repo)). **`Add a repo`** is an accent outline button with the repo icon ([Design system → Buttons](../design/design-system.md#buttons)). The routes and their refusals are in [Add a project → Code repos](./add-project.md#code-repos); a refusal is a toast "Repos not changed" with the reason.
  - **Add a repo** opens a modal "Add a repo to <project>" with the [repo picking form](./add-project.md#picking-repos). It opens on **Clone from a URL**, which clones into Foreman's `repos/`. Choose **A folder** to add an existing repo or create an empty one. The dialog closes once a repo is added. A project just created opens here, to add its repos.
  - **Default branch…** opens a modal "Default branch of <name>": "Its agents start from it, and its merges go to it unless the lead names another branch. Open merge requests keep the branch they go into.", and a select of the repo's branches but the agents' (`wt/*`, `lead/*`); a pick just sets it (`PUT /api/projects/{id}/repos/{repo}/default`, allowed while a team is deployed) and closes it. There is no list of targets to keep (the CEO, 2026-11-06): a merge can go into any branch of the repo but an agent's ([Pipeline and merges → Where a merge goes](./pipeline-and-merges.md#where-a-merge-goes)).
  - **Locate…** opens a modal "Locate <repo>": "Pick its folder now. It must be the same repo: Foreman checks they share a commit.", the folder browser, and **Locate here**, enabled once the folder shown is a git repo ("Open the repo's folder." until then) and not another repo of the project ("That's <name>'s folder."), which saves it. A repo whose record keeps a remote also offers, above the browser, "Or clone it from <remote> into Foreman's repos/, with your git." and **Clone it** ([Add a project → Cloning a repo](./add-project.md#cloning-a-repo)): the way to bring a repo from another machine's record here.
  - **Rename…** opens a modal "Rename <repo>" with the name in a field and **`Rename`**.
  - **Remove…** asks first: "Remove <repo> from <project>?", "Its folder and its branches stay where they are; agents' worktrees of it go. Add it again any time."
  - While a team is deployed on the project, **Rename…** and **Remove…** are disabled, and the menu ends with "Stop the team on this project first to rename or remove it."; the default branch and locating aren't.

## A repo's page

`/projects/<project>/repos/<repo>?branch=<branch>&path=<file>&history=1`, laid out as GitHub does (the CEO, 2026-11-02): a `←` back to the list, the repo's name as words (600 18px; "HQ" for the HQ) and its id (`<repo>/`, Mono 12.5px `--tx4`); a bar with the branch and its latest commit; then the file tree beside the file open, or the history. The page fills the window's height (at least 420px), and the tree, the file and the history each scroll on their own. The section stays selected in the rail.

- **In the URL**, each a step Back returns from (the CEO, 2026-11-02; choosing a branch replaced the entry until then): `branch`, the branch read (`/projects/ledger/repos/api?branch=wt/ledger/tove/LED-44`), so a link opens it: an agent's worktree or a branch in flight on [Deployment](./project-team.md), a review's branch ([Inbox](./reviews.md)); `path`, the file open; `history`, the history instead of the files. A branch the repo doesn't have falls back to its first branch (its default branch, when it has it); a repo the project doesn't have says `<project> has no repo <repo>.` Another branch keeps the file open (a file it lacks shows git's error) and starts its tree folded.
- **The branch** is a button (its name in Mono, `▾`) opening a list to pick from: a box `Find a branch…` (any part of the name, any case; Enter picks the first shown), then the branches, scrolling: the default branch first, then the most recently committed first (the CEO, 2026-10-17; same-second ties by name). A branch: its name (Mono 12.5px), and under it `default branch` for the default branch (where merges go unless the lead names another branch), or whose it is (`wt/<project>/<agent>/…` that agent's in the team on the project, or the one there last, since a later team's agent of the same id takes over the branch; `lead/<project>/<team>/…` that team's lead's; another project's, in a repo they share, `<agent>@<project>`, its instance id; a name from before branches carried the project, nobody's), `N ahead of <default>` when it has commits the default branch hasn't, and `uncommitted changes` (`--accTx`) when the worktree it is checked out in has changes not committed yet. The branch shown is on `--accSoft` and in view when the list opens. `No branch has that name.` when none matches.
- **The latest commit** (a bar beside the branch, `--panel`, 48px high, as is the branch button): its author, its subject, its short hash and its time (hidden under 900px); `No commits yet.` for none; on its right **`N commits`** (on `--raised`). The whole bar is one button (the CEO, 2026-11-02): the history takes the page; there the bar's border is `--accLine` and it reads **`← Files`**, back to the tree and the file (the CEO, 2026-11-02: the history was hidden behind a toggle).
- **The tree** (180–260px): the branch's files as committed, folders first (each with its chevron, opening in place, read when opened), then files; a symlink says `link`, a submodule `submodule` (not opened). A click on a file opens it beside the tree (on `--accSoft` while open). The folders above the file open are open, so a link to a file far down shows where it is; the CEO's own folding stays. An empty repo: `Nothing committed here yet.` It looks like the [Wiki's](./wiki-reader.md#file-tree) (the CEO, 2026-11-02): folder and file icons, and a guide line down each open folder's contents, names in Mono 12.5px.
- **The file**: its path (Mono 12.5px) and size, staying in view while it scrolls; its text in monospace with line numbers (not selected with the text). With no file picked, the root's README (`README`, `README.md` and the like, any case), else its `index.md`, else `Pick a file on the left to read it.`
  - **A Markdown file** (`.md` or `.markdown`, as the server decides) is rendered, with **Rendered / Source**. Its [frontmatter](./wiki-reader.md#frontmatter) is apart, above it, as in the wiki reader, and a `title` field is its heading; Source shows the file whole. Raw HTML stays off and a web link opens in a new tab. **Links into the repo work** (the CEO, 2026-11-03; built 2026-11-03): a relative link resolves against the file's folder, a root-absolute one (`/x.md`) against the wiki root (the folder holding the nearest `wiki.toml` above the file), else the repo root. Each opens on the same repo and branch, like a click in the tree. A folder opens its `index.md`, else its `README.md`, else a list of what it holds; `#anchor` scrolls to that heading, on this file or the one opened; a path the branch doesn't have is marked missing, as in the wiki reader; one climbing out of the repo, or into another repo or the wiki, is text. An image the repo holds loads, under the wiki's image rules (image types only, declared and never sniffed, an SVG sandboxed); any other image shows its text, never loaded (agents write these files).
  - A binary file (a NUL byte) or one over 1 MB says so instead.
- **The history**: the branch's commits, or with **All branches** (segmented with the branch's name above them) every branch's, children before parents (`git log --topo-order`, `--branches` for all), 50 at a time with **Show more**, drawn as a **graph** (the CEO, 2026-11-01): each commit a dot on its lane, lines to its parents, as `git log --graph` lays them out (a commit takes the lane waiting for it, its first parent continues it, another parent takes a free lane; lanes never shift sideways; lane colors `--acc`, `--info`, `--ok`, `--tx3` in turn), rows 52px high. Each row: the short hash, the subject (`merge` beside a merge) with, as a second line in `--accTx` Mono, the branches pointing at that commit (the CEO, 2026-10-17; never `HEAD` or a tag), the author, the time (local, with the date when not today).
- **As committed:** files and history are what the branch has committed, never a worktree's files; the `uncommitted changes` flag is the only sign of work in progress. It refreshes when an agent commits, switches or merges (`team.action`), on `pipeline.changed`, and when projects or their repos appear, go or change (`projects.changed`).
- Diffs stay with the merge requests ([Project pipeline](./project-pipeline.md)).

### Branch cleanup

The Repos section's header has **Clean up branches** left of **Add a repo**, while the project has a code repo: one cleanup over **all its code repos at once** (the CEO, 2026-11-13: one repo at a time was tedious; it replaced a button on each repo's page). It opens a modal, `Clean up branches` (640px wide): `The branches of this project's code repos that can go. Deleting a merged or superseded one loses nothing. Foreman keeps a copy of each for 30 days.`; while they are read (the repos side by side), a spinner and `Reading the branches of each repo: where each one's work stands…`; then the branches, scrolling past 55% of the window's height, in **sections, the safest to delete first** (the CEO, 2026-11-13), each with where its work stands ([Sandboxes and git policy → Cleaning up branches](../architecture/sandboxes-and-git.md#cleaning-up-branches)). A branch of the same name in two repos is two rows, one per repo: its work may stand differently in each.

1. **Agents' branches, merged** (`wt/*`, `lead/*` of this project, and legacy ones): **Merged** (`nothing lost`) and **Superseded** (`all of it is in another branch`). Open and ticked at first.
2. **Your branches, merged**, `Deleted here only: a copy upstream stays.`: **Merged** and **Superseded** (`all of it is in an agent's branch`). Open and ticked at first. Never the repo's default branch, nor one by a long-lived name (`main`, `master`, `develop`, `staging` and the like: [Cleaning up branches](../architecture/sandboxes-and-git.md#cleaning-up-branches)), and never one not merged: it may be work in progress Foreman can't see.
3. **Checked out by agents not at work** (the CEO, 2026-11-19), `Picked, the agent's worktrees go idle at the same commit. Nothing in them is lost.`: **Merged** (`nothing lost`) and **Superseded** (`all of it is in another branch`). Open and unticked at first: nothing is freed unasked. A branch an agent of the project, not at work (its team not deployed, or the agent asleep, stopped or never started), has checked out, merged or superseded in every repo where it has it, can be **freed**: its rows carry `free` (the agent) and show as **one row per agent and branch**, since it is freed in all those repos or none, and Delete sends every {repo, branch} it stands for. The agent's worktrees are detached at the same commit, their changes kept, and the branch deleted ([Sandboxes and git → Freeing a branch](../architecture/sandboxes-and-git.md#freeing-a-branch)). The result lists each worktree left idle (`what: "detached"`, with the agent) next to its branch.
4. **Agents' branches, not merged**: **Not merged** (`work only here`). Folded and unticked at first.
5. **In stray worktrees** (the CEO, 2026-11-11): branches checked out in a folder no agent of any project has (a removed project's kept worktrees, the CEO's own, one since deleted), whatever their work, each with its folder (`in <folder>`, cut, whole in the tooltip) and `not merged` (`--attnTx`) when it isn't: `Checked out elsewhere`, `its worktree goes too, with what git ignores there`. Folded and unticked at first. Picked, the worktree is removed first, its submodules with it (git alone refuses any worktree with a submodule checked out, so Foreman checks it clean first, submodules included, and removes it with `--force`; 2026-11-16); one holding changes not committed, or locked, stays, and the toast says so. A worktree whose folder is already gone is just forgotten.
6. **Staying**: what can't go, dimmed, without a checkbox, each saying why (`checked out by tove@suite` for another project's agent, `checked out in your checkout`, `its review is open`, `an open review merges into it`; for an agent of the project, why it can't be freed: `checked out by tove, who is running`, `…, not merged in web`, `…, a review keeps it in web`, `…, a merge under way in api`, `…, web has a problem`).

A folded section shows its title, `(<count>)` and, once some are ticked, `, <n> ticked`; a click on it opens it. A group's head (on `--raised`) is its checkbox, its name, its count and its hint: it ticks or unticks all its branches, and shows partly ticked when some are. Each row: its checkbox, its repos as they show (`repoName`, 12px `--tx4`: two joined, `api, web`; from three, `<first> +N`; all of them, with their ids, in the tooltip), the branch (Mono 12.5px), `legacy` when it is, for a superseded one `in <branch>` (`+N` when more hold it; all of them in the tooltip), and, at the end of a free row, `<agent>'s worktree` (`worktrees` for several repos). Empty groups and sections don't show; `No branches to clean up.` when there's nothing. **Delete N branches** (danger; disabled with none ticked; a free row counts one branch per repo, as the server does) deletes the pick, reading `Deleting N branches` with a spinner meanwhile ([Design system → Buttons](../design/design-system.md#buttons)), and closes. A toast, `N branches deleted` (branches only), then one line each, only those that apply: the worktrees left idle, by agent (`Left idle at the same commit: tove's Api, Web worktrees; ana's Api worktree.`); any kept, with their repo and why (`Kept: Api wt/… (tove started meanwhile), …`: one checked out meanwhile, one of yours no longer superseded once its holder went); and always last, `Foreman keeps a copy of each for 30 days.` It is `--attn` when something was kept, else `--ok`. `GET /api/projects/:id/branch-cleanup` lists them, `POST` to the same path with `{branches: [{repo, branch}]}` deletes them, each checked again as it goes ([API](../architecture/api.md)).

## Data

`GET /api/projects/:id/branch-cleanup` lists what the branch cleanup offers, each row `{repo, branch, agents, state, supersededBy?, legacy, stays?, stray?, free?}`; `POST` deletes a pick, `{branches: [{repo, branch}]}` → `{removed, kept}` ([API](../architecture/api.md)).

`GET /api/projects/:id/repos` lists the repos and branches, each branch with `agent`: whose worktree has it checked out (the agent whose sandbox, `worktrees/<project>/<agent>/` in Foreman's folder, holds that worktree; `""` for the CEO's checkout or none), and each repo with `idle`: the agents' worktrees of it on no branch, each `{agent, uncommitted}`, by agent (a detached worktree outside the sandboxes is nobody's, left out); `…/repos/:repo/tree?ref=&path=`, `…/file?ref=&path=` (a Markdown file with its frontmatter apart, its links resolved and its headings' ids), `…/image?ref=&path=` (an image a rendered file shows) and `…/log?ref=&skip=` (or `…/log?all=1`, every branch's, each commit with its `parents`; each page with the `total` held) read at a ref ([API](../architecture/api.md)). `:repo` is one of the project's code repos, by its id, or `hq` (each repo listed with `hq: true` for the HQ); anything else is `404`. A ref must name a commit and never starts with `-`; a path is relative and can't climb out with `..`; git then resolves it inside that commit's tree, so nothing outside the repo is reachable. The reads are the Git block's (`Resolve`, `Tree`, `File`, `Log`, `Count`, `Worktrees`, `Detached`), composed by the repos block (`internal/repos`).

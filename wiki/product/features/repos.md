# Repos

A project's **Repos** section ([Project page](./project-page.md); Repositories until 2026-10-31): the project's repos, listed and managed, each opening its own page with its files and history by branch, read-only and as committed. Decided by the CEO on 2026-10-17 ([Repositories card](../../backlog/archive/project-code-tab.md)); only the repos since 2026-10-21, when the work in flight and what merged moved to [Deployment](./project-deployment.md) (the CEO). Body padding `24px 24px 48px`.

## The list

`/projects/<project>/repos`, at most 920px wide: one panel, a row per code repo of the [record](../models/project-config.md#the-project-record), then the **project repo** (`project/`, "The project repo: project.toml and the wiki", no buttons). The CEO moved them here from Settings on 2026-11-01: the repos are managed where they are read.

- **A row** (padding `12px 16px`): its name (Mono 14px 600, `<repo>/`), a link to its page (plain text while it has a problem); under it its path (Mono 12.5px `--tx4`); on the right its branch count (`N branches`, 12.5px `--tx4`), then small buttons: **`Locate…`** (only for a repo with a problem), **`Rename`** and **`Remove`**. Under it, when it has one, its problem in `--err` (a missing folder, or one that is another repo: `Locate it where it went, or remove it from the project`). For a repo without a problem, a line **Main branch** with a select of its branches (its main branch, which its agents start from and its merges go to; changing it is `PUT /api/projects/{id}/repos/{repo}/main`, allowed while a team is deployed), and, when the repo no longer has that branch, in `--err`: "<repo> has no branch <main>: pick its main branch, or agents can't start." (the CEO, 2026-10-21). With none, above the panel in `--err`: `No code repo yet: agents need at least one to work on.` Then **`Add a repo`**. The routes and their refusals are in [Add a project → Code repos](./add-project.md#code-repos); a refusal is a toast "Repos not changed" with the reason.
  - **Add a repo** opens a modal "Add a repo to <project>" with the [repo picking form](./add-project.md#picking-repos) (Existing repo or New empty repo); it closes once one is added.
  - **Locate…** opens a modal "Locate <repo>": "Pick its folder now. It must be the same repo: Foreman checks they share a commit.", and the folder browser; a pick saves it.
  - **Rename** turns the line into a field with the name, **`Rename`** and **`Cancel`**.
  - **Remove** asks first: "Remove <repo> from <project>?", "Its folder and its branches stay where they are; agents' worktrees of it go. Add it again any time."
  - While a team is deployed on the project, **Rename** and **Remove** are disabled, titled "Stop the team on this project first"; adding and locating aren't.

## A repo's page

`/projects/<project>/repos/<repo>?branch=<branch>`: a `←` back to the list and the repo's name (Mono 18px 600, `project repo` beside the project repo's), then a column of its branches (180–240px) beside the browser. The section stays selected in the sidebar.

- **In the URL:** the branch shown is the page's `branch` (`/projects/ledger/repos/api?branch=wt/tove/LED-44`), so a link opens it: an agent's worktree or a branch in flight on [Deployment](./project-deployment.md), a review's branch ([Inbox](./reviews.md)). Choosing a branch replaces it (no new history entry). The branch shown scrolls into the column's view when it changes (a link to one far down the list), never on a refresh. A branch the repo doesn't have falls back to its first branch; a repo the project doesn't have says `<project> has no repo <repo>.`
- **The branches** scroll within the column; the page fills the window's height (at least 360px), and the browser beside it scrolls within it too: a folder, a file (its `← Folder` bar staying in view) or the history. `main` first, then the most recently committed first (the CEO, 2026-10-17; same-second ties by name). A branch: its name (Mono 12.5px), and under it `default branch` for `main` (the project's `main`, the branch merges go into), whose it is (`wt/<agent>/…` that agent's, `lead/<team>/…` that team's lead's), `N ahead of <main>` when it has commits `main` hasn't, and `uncommitted changes` (`--accTx`) when the worktree it is checked out in has changes not committed yet. The selected branch is on `--accSoft`.
- **The browser** shows the chosen branch (the repo's first, `main` when it has one, when the URL names none), with **Files** and **History** (segmented) on the right, and on the left, in Files, the breadcrumbs (the CEO, 2026-10-17):
  - **Files**: the breadcrumbs (`<repo> / src / lib`), then the folder: folders first (`name/`), then files with their size; a symlink says `link`, a submodule `submodule` (not opened). A file shows with `← Folder`, its size, and its text in monospace with line numbers (not selected with the text). A Markdown file is rendered, with **Rendered / Source**: inert, so raw HTML stays off, a web link opens in a new tab, a relative link is text, and an image shows its text, never loaded (agents write these files). A binary file (a NUL byte) or one over 1 MB says so instead. An empty folder: `Nothing committed here yet.`
  - **History**: the branch's commits, or with **All branches** (segmented with the branch's name above them) every branch's, children before parents (`git log --topo-order`, `--branches` for all), 50 at a time with **Show more**, drawn as a **graph** (the CEO, 2026-11-01): each commit a dot on its lane, lines to its parents, as `git log --graph` lays them out (a commit takes the lane waiting for it, its first parent continues it, another parent takes a free lane; lanes never shift sideways; lane colors `--acc`, `--info`, `--ok`, `--tx3` in turn), rows 52px high. Each row: the short hash, the subject (`merge` beside a merge) with, as a second line in `--accTx` Mono, the branches pointing at that commit (the CEO, 2026-10-17; never `HEAD` or a tag), the author, the time (local, with the date when not today).
- **As committed:** files and history are what the branch has committed, never a worktree's files; the `uncommitted changes` flag is the only sign of work in progress. It refreshes when an agent commits, switches or merges (`team.action`), on `pipeline.changed`, and when projects or their repos appear, go or change (`projects.changed`).
- Diffs stay with the merge requests ([Project pipeline](./project-pipeline.md)).

## Data

`GET /api/projects/:id/repos` lists the repos and branches, each branch with `agent`: whose worktree has it checked out (the agent whose sandbox, `<workspace>/agents/<agent>/`, holds that worktree; `""` for the CEO's checkout or none); `…/repos/:repo/tree?ref=&path=`, `…/file?ref=&path=` and `…/log?ref=&skip=` (or `…/log?all=1`, every branch's, each commit with its `parents`) read at a ref ([API](../architecture/api.md)). `:repo` is one of the project's code repos or `project`; anything else is `404`. A ref must name a commit and never starts with `-`; a path is relative and can't climb out with `..`; git then resolves it inside that commit's tree, so nothing outside the repo is reachable. The reads are the Git block's (`Resolve`, `Tree`, `File`, `Log`, `Worktrees`), composed by the repos block (`internal/repos`).

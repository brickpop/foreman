# Sessions

The terminal multiplexer, as a project's **Session** section ([Project page](./project-page.md)). Every agent [instance](../models/instance.md) is a live harness process with a PTY ([Session runner](../architecture/session-runner.md)); the section shows its real terminal in the browser, with keyboard input, copy and paste. It is also where the CEO talks to the team on the project: through the lead by default, or to any member directly.

A project has one team at most ([Deployment](../models/deployment.md#invariants)), so its Session is that team's. There is no list of sessions any more: the CEO follows projects, and each project's Session is in the sidebar under it (the CEO, 2026-10-31: the Sessions screen and its list, `/sessions`, went with the [Project page](./project-page.md); two sessions side by side are still two browser tabs).

## The section

**Header** (padding `10px 16px`, bottom border): the team's **status dot** (its liveliest agent's status, in the order awaiting the CEO, running, starting, queued, idle, done, asleep, stopped, coloured as the agents' own dots, with the status as its title), then `<project> · <team> · [branch ▾]` (the CEO, 2026-11-04): the project's shown name (600 15px), `· <team>` (`--tx3`, a link to the project's [Team](./project-team.md) section), `·` and the shown agent's branch menu ([Agent tabs](#agent-tabs)), and an attention needs-you dot when a request of the team is open. Nothing else: the project's Inbox, Board, Deployment (Stop included) and the rest are in the sidebar.

**No team on the project**: an empty state, `No team is on <project>, so there are no sessions. Deploy one.`, with a primary **`Deploy a team`** opening [Deploy a team](./deploy-team.md) on the project, the team that worked here last chosen at first.

## The URL

The URL is the view, so a reload, a shared link or Back shows the same agent (found 2026-10-16: a reload could open another agent, picked before the team file had arrived, and nothing was kept): `/projects/<project>/session?agent=<agent>`. The agent is named by its id (the project is in the path); a full instance id (`tac@ledger`) is read too, as notifications link it. With no agent, or one not on the team (the one replaced, one gone since a team change), it is the last agent shown on the project while the app runs, else the lead. The section then rewrites the URL to name the agent it shows (replacing it, no history entry); every tab click replaces it too. Deploy opens the new team's Session only once its agents are loaded (it waits for them), or the section would take the project for one with no team.

## Agent tabs

A strip (`--side`, padding `0 12px`) whose tabs scroll horizontally only. Picking a tab keeps the scroll where it is; a tab picked with the keyboard and out of sight scrolls just into view.

1. The **lead first**, with the ["lead" tag](../design/design-system.md#chips-and-badges) unless its name says it already.
2. A 1×20px `--line2` divider and the label **`Direct`** (12px `--tx4`).
3. The other members, in roster order.

Each tab: the agent's 8px status dot (titled with the status), the name (500), then a needs-you dot (`Waiting on you`) while a request of the agent is open (an escalation, or its harness waiting). The agent shown is underlined (inset 2px bottom, `--acc`) and `--tx`, the others `--tx3`. **Its branch shows in the header**, after `<project> · <team>`, as a **branch menu** (the CEO, 2026-11-04; in the header since 2026-10-27): a small bordered button (Mono 11.5px `--tx3`, radius 6) with the branch and a `▾`, joined on its left to a copy button in the same border: it copies the branch name, a check saying it took (the CEO, 2026-11-04). A mouse opens it by **hovering**, once the pointer has rested on it 300 ms, so passing over it on the way to the agent tabs opens nothing (the CEO, 2026-11-05); a click opens it at once. It stays open while the pointer crosses to the menu, closing 200 ms after it leaves both; a click doesn't close it again; a tap or Enter/Space opens it too. The menu: a row per code repo that has the branch, in two groups split by a line (the CEO, 2026-11-04): on top those with work on it (commits beyond its default branch, or uncommitted changes), below the rest, each with what it holds (`2 commits · uncommitted changes`, `1 commit`, `nothing new`) and opening that repo's page on the branch. The repo is never guessed: an agent may have worked in several, all listed. One branch per agent, since `switch` moves all its code repos together; should its repos ever differ (moved outside Foreman), one menu per branch. It comes from the project's repos (`GET /api/projects/:id/repos`, each branch with the agent that has it checked out), refreshed by every git action (`team.action`); none shows before the agent's first start makes its worktrees.

At the header's right end, three labelled buttons open folders on the desktop, all alike (bordered, radius 6, 12px `--tx3`, the label then the Open icon, a box with an arrow leaving it; tooltip `Open on the desktop: <path>`), in this order (the CEO, 2026-11-06): **`Agent folder ↗`**, the shown agent's folder (`<workspace>/agents/<agent>/`, its worktrees, one per repo: the instance's `sandboxPath`; "workspace" already names the project's folder), then the **project's files**, whichever agent is shown: **`Shared files ↗`** (`<workspace>/files/shared/`, the agents' own) and **`File inbox ↗`** (`<workspace>/files/inbox/`, the CEO's files for the agents), last. Each is made if missing, so the CEO can drop files in before the agent first runs ([Project config → The workspace](../models/project-config.md#the-workspace); the CEO, 2026-11-06). A project made before workspaces has no files, and so only `Agent folder`. Nothing copies these paths any more: the folder copy button and the separate Open icon became `Agent folder` (the CEO, 2026-11-06).

**Opening on the desktop**: Foreman runs `open` on macOS, or `xdg-open` on Linux with a display (`DISPLAY` or `WAYLAND_DISPLAY` set), on the folder the server works out (`POST /api/desktop/open`, [API](../architecture/api.md#endpoints)); where it can't (a headless Linux, Foreman in a container, another OS), none of the three buttons shows (`GET /api/desktop`; the CEO, 2026-11-06). A failure shows as a toast. Why this is safe: [Security → Opening folders](../architecture/security.md#opening-folders).

At the strip's right end, always visible: the shown agent's harness label (12.5px `--tx4`; its role was there too until the CEO dropped it as redundant, 2026-11-02: the lead has its tag, the members' roles are on the [Team page](./team-page.md)), then icon buttons (28px square, radius 6, `--tx3`, `--hover` behind on hover, each labelled for screen readers and in a tooltip): **Copy** (two sheets: copies the whole buffer, scrollback included, as plain text; a tick for 1.4 s) and **Line** (a `>_` prompt: toggles the line input; `--accSoft` / `--accTx` while open). An agent with no session has neither. Before them, only while some agent of the team runs on an older prompt, **Reload** (small; [Team definition → Reload](../models/team-definition.md#reload)), the Team header's button (the CEO, 2026-11-03).

Clicking a tab shows that agent, and the keyboard goes to it (the CEO, 2026-10-18): its terminal, or its Line when Line is open, so the CEO types at once; an agent with no session (asleep, queued, stopped) has nothing to take it. **`⌘⇧←` / `⌘⇧→`** (`Ctrl+Shift+←` / `→` off a Mac) do the same for the previous / next tab, round the ends, from anywhere on the page (the CEO, 2026-10-30: without the mouse); like Line's shortcut, the window hears them before the terminal, so the agent never gets them, and in an empty Line input they no longer select to the line's start / end (off a Mac, by word). While Line holds text they never switch, and keep their usual meaning: in Line they select, as in any text box; in the terminal they reach the agent (the CEO, 2026-11-05, twice: a click switches, and the text is kept, see Line input below).

## The terminal

The agent shown fills the section under its tabs. The team's messages and git actions are in the project's [Activity](./project-activity.md) section, never in the terminal.

**Queued agent** (status `queued`: every session slot is taken, idle agents included; the CEO, 2026-10-18): no terminal shows, as for an asleep one; the page says `<Name> is waiting for a session slot: N of M are taken, idle agents included. They start as soon as one frees, and get their messages then.` with a link `Raise the limit in Settings`. It starts by itself when a slot frees (an idle agent going to sleep frees one: [Agent runtime → Idle agents make room](../architecture/agent-runtime.md#idle-agents-make-room)).

**Starting agent** (status `starting`): above its terminal, which stays (its harness may show something before it reports in), a bar with a spinner: `Starting <Name>: its worktrees in <n> code repos, submodules too, then its session. A first start can take a few minutes.` (13px `--tx3`, bottom border; the CEO, 2026-11-04: a start that takes long says so). Foreman prepares the worktrees one repo at a time before the harness runs ([Sandboxes and git policy → Submodules](../architecture/sandboxes-and-git.md#submodules)).

**Asleep agent** (status `asleep`: no session runs until it has work, [Agent runtime → Lazy starts](../architecture/agent-runtime.md#lazy-starts)): no terminal, and no `Line` or `Copy`. Centered instead: `<Name> is asleep: no session runs until there's work for them.` (13.5px `--tx3`) and an accent outline **`Start <Name>`** button with a play icon ([Design system → Buttons](../design/design-system.md#buttons); the CEO, 2026-11-04), which wakes it; the terminal appears once it runs. A failure shows an error toast. A **stopped** agent (two crashes, or a start that failed) gets the same: `<Name> stopped: <reason>. Messages for them wait until you start them again; they pick up their conversation.` and **`Start <Name> again`**. The reason is the instance's `stop_reason` ([Instance](../models/instance.md)): `couldn't start: <why>` (a repo without its default branch, say) or `it exited twice in a row (code <n>)`; without one (a stop from before reasons were kept), `<Name> stopped.` (the CEO, 2026-10-21). An agent that exits cleanly (`/exit`) is asleep ([Agent runtime → Restarts](../architecture/agent-runtime.md#restarts)).

**Body**: a real terminal emulator on `--term`, in the CEO's terminal font (JetBrains Mono 13px by default, [Settings](./settings.md#appearance)), line height 1.25.
- Full ANSI (colors, cursor movement, alternate screen), as the harness renders it.
- Scrollback is replayed from the session log when a terminal opens ([Persistence](../architecture/persistence.md)); the live stream follows.
- Native text selection, copy and paste; clickable links. When the harness turns on mouse reporting (Claude Code does in some views), a drag goes to it rather than selecting: Option-drag on a Mac (Shift-drag elsewhere) still selects (found by the CEO, 2026-10-16).
- **Shift+Enter** types the harness's newline keystroke (a new line without sending), the same as in the line input: a terminal alone can't tell it from Enter.
- Resizing keeps the bottom anchored, as a native terminal does: a terminal that gets shorter (Line opening, the draft box appearing, a smaller window) sends its top lines into the scrollback, and growing back brings the same lines down again. Claude Code relies on it: on every resize it repaints the screen from its top with the last rows of its view and takes everything above as being in the scrollback. xterm.js alone deletes the rows below the cursor on a shrink and adds blank rows at the bottom on a grow, so lines vanished from the middle, or doubled each time Line opened (found by the CEO, 2026-11-05; checked against a recorded Claude Code session). So Foreman scrolls the screen up before a shrink and puts the cursor on the last row before a grow, holding output meanwhile ([Technical debt](../../technical-debt.md#resizing-the-terminal-from-the-bottom)). Blank rows at the bottom go first only on a screen never filled; a full-screen app (the alternate screen) is left to repaint itself.
- The terminal size is propagated to the PTY on every resize. One PTY has one size, so when several browser tabs show the same instance, **the most recently focused view sets it**; the others render that size (letterboxed or scrolled).
- Opening a terminal (or reconnecting) replays the screen and its scrollback; it is drawn hidden and shown at the bottom once drawn (a 150 ms fade), so it never flashes by scrolling (at most 600 ms hidden if nothing arrives).
- Auto-scroll follows output while the view is within 160px of the bottom; scrolling up stops following.
- Keystrokes go straight to the PTY, raw, always ([API](../architecture/api.md), `WS /ws/pty/:instance`). Foreman doesn't interpret them.

**Messages wait on the CEO's draft** (the CEO's request, 2026-10-16). Text the CEO types straight into an agent's terminal and hasn't sent yet is a **draft**, and a delivery would land on it. So while one is there, that agent's messages wait, and an attention box above the line input says so: inset from the edges (`8px 12px`), radius 8, a 2px `--attn` border on all four sides, `--attnSoft`, `--attnTx`, so it is never mistaken for the harness's own status line. It says `1 message waiting for your line: send or clear it. 0:12`, with tiny **`Pause`** / **`Resume`** and **`Send now`** buttons. Send now releases the hold immediately, including when paused, using the same unfinished-draft separator as countdown expiry; delivery still waits for the agent to be idle. The countdown starts at 0:20 and runs only while the CEO isn't typing (5 s after the last key), so they aren't rushed; `(waits while you type)` says so, and Pause holds it until resumed. Sending the line (from the terminal or the Line input) lets the messages follow at the agent's next idle (or at once, if the Enter started nothing), and until they are in, the box stays, without countdown or Pause: `1 message waiting: it goes in when Mara's turn ends.` (the CEO saw the box vanish on sending and took the messages for lost, 2026-10-30); clearing it (Ctrl+U, Ctrl+C, Backspace to empty) lets them through at once. At 0:00 they go after the draft, separated by a blank line, `---` and `The CEO's text above is an unfinished draft: don't act on it yet.` ([Team tools → Delivery](../architecture/team-tools.md#delivery)). Foreman tells a draft from other keys by what is typed: printable text makes it, Enter, Ctrl+C and Ctrl+U end it, navigation and function keys preserve the draft and restart the quiet period. A standalone Escape input event preserves the draft and cannot consume the next key. Automatic terminal replies (including Codex color queries) never create a draft or reset the typing quiet period, including continuations after a sequence introducer. Each xterm input event travels as one WebSocket message: an event containing only Escape is a keypress, not the start of a terminal reply. Accepted: text typed into a harness's own dialog counts as a draft too, and clearing the prompt with the harness's own keys (Claude Code's Esc Esc) isn't seen, so the messages wait for the countdown.

**Line input** (optional mode, for paste or mobile): a light box under the terminal (margin `4px 12px 12px`, radius 8, 1px `--line2` turning `--line3` on focus instead of the focus ring, `--term`, padding `12px 16px`) holding an accent `❯` (Mono 500 13px `--accTx`) and a borderless text box (line-height 1.6) that grows with its lines (up to 8). Enter sends it through Foreman (`POST /api/instances/:id/line`), which types it the way it types a delivery and in the same queue, so the two never mix: each line, each line break as the harness's **newline keystroke** ([Harness adapters](../architecture/harness-adapters.md)) after a short pause, then Enter after a pause. Sent in one burst, the Enter reached Claude Code as part of a paste (a line break, not sending; found 2026-10-16). A refusal (the agent stopped) shows beside the box. Shift+Enter starts a new line; an empty input still sends Enter. Typing `@` (at the start or after a space) offers the teammates' names, starting with what follows it (a small list above the box; the arrows choose, Enter or Tab takes one, Escape closes the list, a click works too); the name goes in plain, without the `@`, since a harness may read `@` as its own file mention (Claude Code does, and its file list would take the Enter). The mode is switched on by the **`Line`** button at the end of the agent tabs, or **Ctrl+Shift+L** (**Cmd+Shift+L** on a Mac), anywhere on the screen (caught before the terminal, so the agent never gets it; Ctrl+L alone, and on a Mac every Ctrl key, still reach the agent). Opening Line puts the keyboard in it. The shortcut from the terminal goes back into an open Line; from Line, it closes it. Escape or the button also close it. Closing puts the keyboard back in the terminal. **The text typed and not sent is kept per agent** (the CEO, 2026-11-05): switching to another agent and back finds it there, Line open with it; it lasts until the page reloads, and while any agent still on a session has some, a reload or closing the tab asks first (the browser's own `Leave site?` prompt). Sending clears it, also when the send ends after the CEO switched away. Placeholders:

| Situation | Placeholder |
|---|---|
| Instance is `awaiting` (its harness asks) | `Reply to <Name>…` |
| Lead | `Tell <Name> what you need. They’ll delegate.` |
| Other member | `Direct instruction to <Name>…` |

## Talking to the team

- Typing to the **lead** is a request; the lead delegates through [Team tools](../architecture/team-tools.md) (`ask`, `handoff`).
- Typing to a **member** is a direct instruction. It goes raw to the member's terminal; Foreman posts nothing to the lead. The member tells the lead itself when the instruction matters to the team, as its [session prompt](../architecture/session-prompt.md#talking-to-the-ceo) asks.
- Typing to an `awaiting` instance answers its harness's dialog, and the card it raised resolves with the harness's next activity ([Requests](./requests.md)). An `escalate` request is answered on its card (Dashboard, Inbox), never by typing.

# Glossary

- **Home**: Foreman's machinery on this machine, `~/.foreman` (or `--home`); one Foreman runs per machine. It holds this machine's `settings.toml`, each agent's harness folder and Foreman's state; nothing in it is in a repo. See [Home](./models/home.md).
- **Foreman's folder**: what the CEO owns, `~/foreman` by default (the `foreman_folder` setting, read at start, no UI to change it): Foreman's HQ (`hq/`), each project's HQ and files (`projects/<id>/`) and the agents' worktrees (`worktrees/<id>/`). See [Home → Foreman's folder](./models/home.md#foremans-folder).
- **Foreman's HQ**: `hq/` in Foreman's folder, a git repo holding the team files (`teams/`) and the CEO's instructions to every agent (`instructions.md`); every UI save is one commit. See [Home → Foreman's HQ](./models/home.md#foremans-hq).
- **Project**: a project record plus its HQ; its code repos live anywhere in the CEO's home folder. See [Project config](./models/project-config.md).
- **Project page**: where the CEO works on a project, its sections listed in the sidebar under the project open: Session, Inbox, Wiki, Board, Repos, Deployment, Activity, Settings. See [Project page](./features/project-page.md).
- **Session** (the section): a project's team at work, one agent's terminal at a time. See [Sessions](./features/sessions.md).
- **Inbox**: a project's section of what waits on the CEO there: its reviews, then its other requests. See [Reviews → The Inbox](./features/reviews.md#the-inbox).
- **Not on this machine**: a project whose record is in `projects.toml` but whose HQ isn't at `projects/<id>/hq/` here (another machine's). Listed only on the Dashboard, with **Bring here**, which clones its HQ. See [Home → A new machine](./models/home.md#a-new-machine).
- **Restore**: replacing the HQ a first start made, while still untouched, with a clone of another machine's Foreman's HQ. See [Home → A new machine](./models/home.md#a-new-machine).
- **Project record**: a project's entry in `projects.toml`, in Foreman's HQ (its id, display name, code repos by name, origin, root commit and default branch: what travels between machines), and this machine's part in `state.db` (its profile, each repo's path). Edited from the UI, or `projects.toml` by hand. See [Project config → The project record](./models/project-config.md#the-project-record).
- **HQ** (the project's): `projects/<id>/hq/`, the one git repo Foreman reserves in every project: `project.toml` and the project's knowledge base, a wiki at its root (`$PROJECT_HQ` in each agent's environment). One live checkout shared by every agent of the project, writable by the lead only; named `hq` in the API and the `commit` tool. See [Project config → The project's HQ](./models/project-config.md#the-projects-hq).
- **Repository** (code repo): a git repo the CEO adds to a project by its path, anywhere in their home folder. Foreman never moves one; on request it creates an empty one, or clones one from its URL into `repos/` of Foreman's folder. A repo gone from its path blocks starting the project's agents until it is located or removed.
- **Default branch**: a code repo's branch that agents start from, idle desks follow, and merges go to unless the lead names another branch: `main` when the repo has one, otherwise the one the CEO picks when adding it, changed from [Repos](./features/repos.md) to any branch of the repo but an agent's. One of the CEO's branches.
- **The CEO's branches**: every branch of a code repo but an agent's (`wt/*`, `lead/*`): the default branch and any other the CEO's git account makes (a release branch, say). No agent writes one; they change only by the CEO's merge or the CEO's own git. See [Pipeline and merges → Where a merge goes](./features/pipeline-and-merges.md#where-a-merge-goes).
- **Target**: the branch a merge request goes into, one of the CEO's branches (its repo's default branch unless the lead names another). There is no list of targets: any of the CEO's branches can be one.
- **Wiki bundle**: the project's HQ itself, its knowledge base at its root: a folder of Markdown files with YAML frontmatter, plus `wiki.toml`. Compatible with the agentic-wiki / WikiShell format. See [Wiki engine](./architecture/wiki-engine.md).
- **Board**: a kanban view over wiki entries, declared in `wiki.toml` under `[[tool.wikiview.board]]`. See [Board](./features/board.md).
- **Team definition**: a reusable roster and playbook, stored in `hq/teams/<team>.toml`, in Foreman's HQ. See [Team definition](./models/team-definition.md).
- **Agent (soul)**: one member of a team definition: name, role, personality, skills and job description; what it runs on is its project's profile. One soul can run in many deployments. See [Agent soul](./models/agent-soul.md).
- **Deployment**: a team assigned to a project; a project has one at most. The goal is the project's, in its wiki. This is runtime state, not config. See [Deployment](./models/deployment.md).
- **Instance / session**: one agent running in one deployment. It is a live harness process with a PTY. Identified as `agent@project` (e.g. `mara@ledger`). See [Instance](./models/instance.md).
- **Project files**: `projects/<id>/files/` in Foreman's folder, shared with the project's agents whatever team is deployed: `inbox/`, the CEO's files for them (read-only for them), and `shared/`, their data that outlives a task and a team (every agent writes it). Not the project's Inbox section. See [Sandboxes and git policy → Layout](./architecture/sandboxes-and-git.md#layout).
- **Sandbox**: an agent instance's working directory, `worktrees/<id>/<agent>/` in Foreman's folder: its worktrees of the code repos, disposable. The live project's HQ is mounted beside it at its real path, `projects/<id>/hq/`, the same in every container. See [Sandboxes and git policy](./architecture/sandboxes-and-git.md).
- **Worktree** (of an instance): the instance's git worktree of one code repo, `worktrees/<id>/<agent>/<repo>/`, made with `git worktree add` on the host the first time the agent opens that repo (and again if deleted by hand) ([Opening a repo](./architecture/sandboxes-and-git.md#opening-a-repo)), and idle on no branch (detached at the repo's default branch) between pieces of work. It shares the repo's objects and branches, so a hand-off only names a branch. Agents read git there; every git write goes through Foreman's `switch`, `commit` and `merge` tools. See [Sandboxes and git policy](./architecture/sandboxes-and-git.md#layout).
- **Worktree branches**: `wt/<project>/<agent>/<topic>`, where members do one piece of work (the topic usually a card id), made by `switch`. No branch is made for an idle agent.
- **Lead branch**: `lead/<project>/<team>/<topic>`, made by `switch`, where the lead integrates handoffs; a lead can have any number. Lead branches are the only source of merge requests, each into one of the CEO's branches, one open merge request per branch at a time.
- **Harness**: the CLI program that runs an agent (Claude Code, Codex CLI, Pi, Hermes Agent, or a custom command). See [Harness adapters](./architecture/harness-adapters.md).
- **Profile**: a harness and its credentials, under a name (`default`: Claude Code and its login), the CEO's on this machine, kept in `~/.foreman/profiles/`. A project picks the one its agents run on (`default` unless set). See [Session runner → Credentials](./architecture/session-runner.md#credentials).
- **Session runner**: where a harness process runs and how Foreman attaches to its terminal (a Podman container in v1). See [Session runner](./architecture/session-runner.md).
- **Team tools**: the MCP tools Foreman exposes to every harness: `ask`, `reply`, `handoff`, `contribute`, `escalate`, `open`, `switch`, `commit`, `merge`, `abort_merge`, `set_submodule` and `request_merge`; agent-to-agent traffic through them is **team messages**. Called "ACP" in the original PRD. See [Team tools](./architecture/team-tools.md).
- **Session driver**: how Foreman drives a harness session: through its TUI in a PTY (v1), or later through the Agent Client Protocol. See [Harness adapters](./architecture/harness-adapters.md#session-drivers).
- **Agent Client Protocol (ACP)**: Zed's open protocol for driving coding agents over JSON-RPC (prompts in; messages, tool calls and permission requests out). A future session driver; not the team tools. See [Harness adapters](./architecture/harness-adapters.md#session-drivers).
- **Contribute**: the team tool through which an agent without write access to the knowledge base adds to it: `contribute(kind, title, body)` with `kind` finding, proposal or note. Foreman saves it as a draft in the project files' `shared/contributions/`, outside git, and tells the lead, who files it in the wiki or drops it (the CEO, 2026-11-18). See [Team tools](./architecture/team-tools.md#tools).
- **Switch, commit, merge, abort_merge, set_submodule**: the team tools through which agents write git, since every repo's `.git` (the HQ's included) is read-only in their containers: `switch(branch, from?)` switches their worktrees to one of their branches, creating it from `from` (any branch or commit) or the default branch if it doesn't exist yet, `commit(commits)` commits the repos they name, each with its own message, on their own branch (and, for the lead, the live project's HQ, named `hq`), `merge(branch)` merges any branch into their worktrees, `abort_merge()` backs out of an unfinished one, and `set_submodule(repo, path, ref, url?)` pins a submodule to a commit of its repo, adding it with `url`. Foreman runs them on the host. See [Sandboxes and git policy → Agents and git](./architecture/sandboxes-and-git.md#agents-and-git).
- **Request**: something that needs the CEO, of one of five kinds: approval, question, review, finding, blocked. See [Requests](./features/requests.md).
- **Playbook**: the team's written workflow (who does what, when, and when to escalate). It is part of the team definition.
- **Gates**: project rules that always escalate to the CEO (e.g. "new dependency"). They are part of project config (`always_ask_ceo`).
- **Card** (board card): a wiki task entry shown on a [board](./features/board.md). "Card" means only this; members usually work on one card per topic branch (`wt/<project>/<agent>/<card>`).
- **Work item**: one agent's branch on its way into the lead branch (in worktree → handed to lead → lead reviewing → integrated). Informational: it never needs the CEO. See [Work item](./models/work-item.md).
- **Merge request**: the lead's request, through `request_merge(branch, title, body?, entry, into?)`, to merge a lead branch into its target in one repo, a branch of the CEO's (its default branch unless `into` names another), explained by a wiki entry and carrying the integrated work items; decided on its branch's review. See [Merge request](./models/merge-request.md) and [Pipeline and merges](./features/pipeline-and-merges.md).
- **Review**: the CEO's review of one lead branch, across every repo it changed: its diff file by file, the CEO's comments to the lead, and the decision (Merge the repos ticked, Request changes, Dismiss). It raises the pipeline's only request, the review request. See [Review](./models/review.md) and [Reviews](./features/reviews.md).
- **Request panel**: the UI component that shows one [request](./models/request.md) on the Dashboard and in a project's Inbox (Needs you).
- **Chief of Staff (CoS)**: the built-in, Foreman-owned agent session that creates teams, hires and refines members, from its own page. See [Chief of Staff](./features/chief-of-staff.md).
- **CEO**: the single human user of Foreman.
